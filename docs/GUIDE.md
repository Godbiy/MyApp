## 1. Як працює пайплайн

### Що його запускає

У `.github/workflows/ios.yml` чотири тригери:

| Подія | Що робить |
|---|---|
| `push` у `main` | збірка → `.ipa` в артефакти + оновлення релізу `latest` |
| `push` тега `v*` | те саме плюс окремий іменований GitHub Release |
| вручну (`workflow_dispatch`) | кнопка **Run workflow** у вкладці Actions |
| `pull_request` | тільки перевірка, що нічого не зламалось |

Плюс `concurrency`: якщо пушнути двічі підряд, попередня збірка скасовується, щоб не гріти чергу даремно.

### Що відбувається всередині

Раннер — свіжа віртуалка macOS від GitHub, яка живе рівно одну збірку і вмирає. Xcode на ній уже передвстановлений.

**1. Checkout** — клонує репо на віртуалку.

**2. Toolchain info** — друкує версію Xcode/Swift. Чисто діагностика: коли через півроку збірка раптом впаде, у логах буде видно, що GitHub підняв Xcode на нову мажорну версію.

**3. Install XcodeGen** — `brew install xcodegen`, ~20 секунд.

**4. Generate Xcode project** — читає `project.yml` і створює `Sklo.xcodeproj`.

> **Чому `.xcodeproj` не лежить у git.** Файл проєкту Xcode — це XML на тисячі рядків, де кожен Swift-файл прописаний вручну з UUID-ами. Створити його без Xcode неможливо, а редагувати з Windows — самогубство. XcodeGen перевертає логіку: проєкт описується в ~30 рядках YAML, а `.xcodeproj` стає розхідником, який генерується щоразу заново. Саме тому він у `.gitignore`.
>
> **Практичний наслідок:** новий Swift-файл просто кладеться у `Sources/Sklo/` — ніде більше реєструвати не треба, бо `project.yml` включає теку цілком.

**5. Build for simulator** — компіляція під симулятор у Debug.

> Цей крок нічого не виробляє, і він тут навмисно. Якщо в коді синтаксична помилка, він впаде за ~30 секунд із чітким `ContentView.swift:12: error:`. Без нього та сама помилка ловилась би аж на кроці archive — довше й серед значно шумніших логів.

**6. Archive for device** — справжня збірка під залізо: Release, SDK `iphoneos`, arm64.

Ключові прапорці:

```
CODE_SIGN_IDENTITY=""  CODE_SIGNING_REQUIRED=NO  CODE_SIGNING_ALLOWED=NO
```

Вони кажуть Xcode «збери, але не підписуй». Без них крок падає з `No signing certificate "iOS Development" found`, бо сертифіката в нас нема.

Тут же підставляється `CURRENT_PROJECT_VERSION` = номер запуску воркфлоу, тож номер білда автоматично дорівнює номеру збірки. На екрані застосунку видно `Build 7`, і одразу зрозуміло, яку саме збірку тримаєш у руках.

**7. Package unsigned .ipa** — пакування вручну:

```bash
mkdir -p Payload && cp -R Sklo.app Payload/ && zip -qry Sklo-unsigned.ipa Payload
```

> **Чому не штатний `xcodebuild -exportArchive`.** Він обов'язково вимагає сертифікат і provisioning profile, тобто платний акаунт. Але `.ipa` за своєю природою — звичайний zip, усередині якого тека `Payload/<Name>.app`. Формат відкритий, тож ми збираємо його самі.

**8. Upload artifact** — кладе `.ipa` у Artifacts, зберігається 30 днів. `if-no-files-found: error` — щоб збірка чесно впала, якщо `.ipa` раптом не створився, а не «позеленіла» з порожнім артефактом.

**9. Update `latest` release** — перезаписує рухомий реліз `latest`, щоб існувало постійне посилання на свіжий `.ipa`.

### Час і гроші

~1.5 хвилини на збірку. Репо public, тому Actions безлімітні й безкоштовні. (Був би private — macOS рахується з 10× множником, і 2000 безкоштовних хвилин перетворились би на ~200 реальних, тобто ~40 збірок на місяць.)

## 2. Як забрати .ipa

Три способи, від найзручнішого:

**Постійне посилання на свіжу збірку** — оновлюється автоматично при кожному пуші в `main`:

```
https://github.com/Godbiy/MyApp/releases/download/latest/Sklo-unsigned.ipa
```

**Через термінал:**

```bash
gh run download --name Sklo-unsigned-ipa
```

Забирає з останньої успішної збірки й одразу розпаковує — `.ipa` опиняється в поточній теці.

**Через вкладку Actions:** репо → **Actions** → останній зелений ран → донизу до **Artifacts** → `Sklo-unsigned-ipa`.

> У теці `dist/` лежить закомічений `.ipa` — це **знімок на момент коміту**, він не оновлюється сам. Для актуальної збірки завжди бери реліз `latest`.

> **Чому посилання таке довге, а не звичне `/releases/latest`.** Реліз `latest` позначений як пререліз, щоб не перебивати справжні версійні релізи з тегів `v*` у списку. А шорткат `/releases/latest/` у GitHub пререлізи навмисно пропускає — і віддає 404. Пряме посилання по тегу працює незалежно від цього.

## 3. Як поставити на айфон

Головне зрозуміти суть: **`.ipa` з CI непідписаний, і Apple його в такому вигляді не пустить.** Підпис накладається на твоєму ПК твоїм Apple ID. Це штатний механізм Apple для розробників, не злом — просто безкоштовний варіант має жорсткі обмеження.

### Крок 1. Підготувати Windows (один раз)

Sideloadly спілкується з айфоном через драйвери Apple, які їдуть у комплекті з iTunes. Тут є пастка, на якій спотикаються майже всі:

> **Версія iTunes із Microsoft Store не підходить** — вона в пісочниці й не віддає драйвери назовні. Потрібен класичний інсталятор із сайту Apple.

1. Якщо стоїть iTunes або iCloud з Microsoft Store — **видалити**.
2. Поставити [iTunes для Windows](https://www.apple.com/itunes/download/win64) — саме `.exe` з сайту Apple.
3. Поставити [iCloud для Windows](https://support.apple.com/icloud-windows) — теж не зі Store.
4. Поставити [Sideloadly](https://sideloadly.io/).

### Крок 2. Увімкнути Developer Mode на айфоні (один раз)

На iOS 16+ без цього застосунок встановиться, але не запуститься:

**Налаштування → Приватність і безпека → Режим розробника → увімкнути → перезавантажити телефон.**

Пункт може не з'явитися, доки на телефон уперше не спробує щось поставитись. Якщо його не видно — зроби спершу крок 3, і він виникне.

### Крок 3. Поставити застосунок

1. Під'єднати айфон кабелем, на телефоні підтвердити **Довіряти цьому комп'ютеру**.
2. Відкрити Sideloadly — він має побачити пристрій.
3. Перетягнути `Sklo-unsigned.ipa` у вікно.
4. Вписати свій **Apple ID**, натиснути **Start**.
5. Ввести пароль. За ввімкненої двофакторки знадобиться [app-specific password](https://appleid.apple.com), а не звичайний пароль.

> **Порада, яка економить нерви:** Sideloadly дозволяє задати Bundle ID. Постав його раз (`com.godbiy.sklo`) і **не міняй між переустановками**. Безкоштовний акаунт має ліміт 10 App ID на 7 днів — якщо щоразу генерувати новий, ліміт вигорить за пару днів, і ти застрягнеш до кінця тижня.

### Крок 4. Довірити сертифікат

Перший запуск дасть помилку «Ненадійний розробник». Це нормально:

**Налаштування → Загальні → VPN і керування пристроєм → твій Apple ID → Довіряти.**

Тепер застосунок запускається.

### Обмеження безкоштовного Apple ID

| | |
|---|---|
| Підпис живе | **7 днів**, далі застосунок перестає відкриватись |
| Активних застосунків | 3 одночасно |
| Нових App ID | 10 на 7 днів |
| Недоступно | push-сповіщення, iCloud, Apple Pay, HealthKit та інше, що вимагає платного акаунта |

Переустановка тим самим Sideloadly скидає лічильник на нові 7 днів, і **дані застосунку зберігаються**.

Якщо 7 днів почнуть дратувати — [AltStore](https://altstore.io/) робить те саме, але переустановлює сам у фоні, поки ПК увімкнений і в тій же Wi-Fi мережі.

## 4. Щоденний цикл розробки

```bash
# 1. правиш або додаєш файли в Sources/Sklo/

# 2. пушиш
git add -A && git commit -m "що зробив" && git push

# 3. чекаєш ~1.5 хв
gh run watch

# 4. забираєш збірку
gh run download --name Sklo-unsigned-ipa

# 5. перетягуєш .ipa у Sideloadly -> Start
```

Кроки 4–5 потрібні, лише коли хочеш побачити зміни на телефоні. Щоб просто перевірити «чи компілюється» — достатньо зеленого чекмарка з кроку 3.

## 5. Коли переходити на платний акаунт

Apple Developer Program ($99/рік) знімає все вище: підпис живе рік, застосунків скільки завгодно, доступні push і решта можливостей, і головне — з'являється **TestFlight**.

Пайплайн тоді змінюється так:

- сертифікат + provisioning profile + App Store Connect API key кладуться в GitHub Secrets;
- ручне пакування `.ipa` замінюється на штатний `xcodebuild -exportArchive`;
- додається крок заливки в App Store Connect.

Після цього кабель і Sideloadly не потрібні взагалі: пушнув у `main` — за кілька хвилин збірка сама прилітає на телефон сповіщенням TestFlight.

Переробити це — приблизно година роботи. Зараз воно не потрібне.
